# Project Plan — cave

## Roadmap

Rationale: `docs/architecture_design.md` › Delivery Approach.

- [x] Phase 1: Backend Spike & Decision
  - Outcome: Bubblewrap (`bwrap`) selected as isolation backend (9.28 ms startup overhead, rootless, clean tmpfs masking). Direct terminal inheritance selected (native signals/TTY passthrough, no relay). Rust selected as CLI implementation language (<2ms overhead, single static binary, `CommandExt::exec` process replacement). Loosely coupled to external `bwrap`. Reusing host `/tmp` supported via `--dir /tmp`. Spike script preserved at `vdesign/utils/spike-bwrap.sh`.
- [x] Phase 2: Walking Skeleton — `cave claude`
  - Outcome: Implemented in Rust (`src/cli.rs`, `src/policy.rs`, `src/bwrap.rs`). Embedded profiles (`src/profiles.toml`) with Claude Code profile (RW state `~/.claude/`, `~/.claude.json`, RO runtime `~/.local/share/claude`). Mount order rule enforces defaults → profile → CWD → `--dir` / `--ro-dir` overrides. Private tmpfs for `/tmp`, `/run`, `/var/tmp`, and `$HOME`. Sensitive paths hidden. Host environment sanitized (`SSH_AUTH_SOCK`, `DBUS_SESSION_BUS_ADDRESS` unset). Direct terminal inheritance via `execve`. Hardened boundary tests (12 unit, 11 boundary tests green), typed state entries with valid JSON seeding (`init = "{}"`), and raw OsString passthrough. Initial `--doctor` diagnostics check bwrap availability and AppArmor unprivileged user namespace sysctls; sandbox DNS and `/var/run` symlink checks deferred to Phase 3. Live interactive verification confirmed on host terminal (direct TTY, SIGWINCH resize, colors, Ctrl-C, Ctrl-Z/fg); a setting changed inside `cave claude` (`/config`) persisted directly to native host `claude`, confirming live host state writes on existing inode without triggering kernel mount-point `EBUSY`. Added startup overhead measured at 7.37 ms (budget < 100ms).
- [x] Phase 3: Agent Profiles & Diagnostics
  - Outcome: Added embedded profiles for `agy` (`~/.gemini` RW state permitting runtime `agentapi` execution bridge generation), `aider` (`~/.aider` RW state, `~/.aider.conf.yml` RO runtime), and shell profiles (`sh`, `bash`, `zsh`). Added `~/.local/share/uv` to `ro_home` defaults so uv tool symlinks resolve. Profile mount loop renders `state` before `runtime` so read-only subpath binds override parent read-write state directories. Unknown-agent warning emitted to stderr with `--dir` hint; suppressed for shells. User config file (`${XDG_CONFIG_HOME:-$HOME/.config}/cave/profiles.toml`) layered over embedded defaults with append semantics, downgrade-by-re-declaration, and fatal located parse errors. Config is loaded once and passed in as `&ConfigData`: neither `build_mount_plan` nor `prepare_host_state` reads config, and `prepare_host_state` is the only host write. Completed `cave --doctor` diagnostics: verifies `bwrap` availability, unprivileged user namespaces, AppArmor restriction, `/var/run` symlink to `/run`, sandboxed `/etc/resolv.conf` nameserver presence, non-fatal external DNS lookup, and prints loaded config sources with effective merged profile table. Verified live interactive session persistence across host and cave boundaries for `agy` and `claude`. Test suite expanded to 17 unit tests and 19 boundary tests (36 tests, all passing, 0 clippy warnings). Measured release startup overhead: 8.96 ms (budget < 100 ms).
- [x] Phase 4: Arch Linux Packaging & Distribution
  - Outcome: Created Arch Linux VCS package specification in `packaging/arch/PKGBUILD` for `cave-git` (provides/conflicts with `cave`, runtime dependency `bubblewrap`, build dependencies `cargo`/`git`). Dynamic `pkgver()` supports git tags and commit count fallbacks. Formalized project licensing with root MIT `LICENSE` and enhanced `Cargo.toml` metadata (description, repository, homepage, license). Reconciled `README.md` with exact installation semantics (git branch build vs local cargo testing), clarified default `~/.config` inheritance isolation, and removed privileged `.npmrc` from config examples. Validated package build with `makepkg` pulling from GitHub into `cave-git-*.pkg.tar.zst`, verified with `tar -tf` containing `/usr/bin/cave`, documentation, license, and `/usr/share/doc/cave/profiles.toml.example` from `examples/profiles.toml`.
- [x] Phase 5: SSH via the host ssh-agent
  - Outcome: Host `ssh-agent` socket forwarded read-only at `/run/user/$UID/ssh-agent.sock` (with `0700` runtime directory permissions via `MountEntry::DirPerms` and `MountPlan::set_env` overrides) when `SSH_AUTH_SOCK` resolves to a valid Unix socket (`policy::resolve_ssh_socket`). Added `.ssh/config` and `.ssh/known_hosts` to `defaults.ro_home` while keeping private keys (`~/.ssh/id_*`) hidden on the empty `$HOME` tmpfs. Masked `/etc/ssh/ssh_config.d` with an empty `tmpfs` (skipping missing `tmpfs` paths in `build_mount_plan` via `p.exists()`) so OpenSSH does not abort on host root-owned (`nobody` in userns) drop-in files. Added `--no-ssh` CLI flag and single-line stderr warning on stale `SSH_AUTH_SOCK`. `build_mount_plan` takes the resolved socket path as given (`Option<&Path>`) and reads no config and no environment (it does stat and canonicalize paths on disk). Extended `cave --doctor` to verify both offline config parsing (`ssh -G github.com`) and key visibility (`ssh-add -l`) inside the sandbox. Verified live with `ssh -T git@github.com`, `git ls-remote`, and live branch push/delete over SSH. Test suite expanded to 25 unit tests and 20 boundary tests (45 tests, all passing, 0 clippy warnings).
- [x] Phase 6: Toolchains — `cave --with flutter`
  - Outcome: Added `[toolchains.NAME]` configuration table beside `profiles` in `ConfigData` and `UserConfigData` with `requires`, `rw_cache`, `runtime`, and `check_tcp` fields (`ToolchainConfig`, `UserToolchainConfig`, `TcpCheckConfig`). Layered in `merge_user_config` with append and move-between-lists rules. Added repeatable `--with NAME` option in `cli::parse_args` accepted for execution and diagnostics (`cave --doctor`). Unknown toolchain names exit 1. Resolved toolchains mount in `build_mount_plan` after the agent profile and before the working directory, in `--with` argument order, rendering `rw_cache` mounts before `runtime` mounts. `build_mount_plan` checks candidate paths on disk and warns when the working directory is `/` or `$HOME`; `cli::check_warning` warns for such `--dir` / `--ro-dir` paths in `parse_args`. Toolchain entry expansion and classification unified in `policy::resolve_entry` and `policy::resolve_toolchain` over the `ExpansionLookup` trait (`SystemLookup` reads the environment and finds binaries with `bwrap::which_binary`, which falls back to `/usr/bin` only when `PATH` is unset). Enforced fatal boundary protection: toolchain entries resolving to `/`, `$HOME`, or an ancestor containing `$HOME`, as written or through a symlink, exit 1 naming toolchain, entry, and resolved path without using `--dir` warnings. Unresolved or missing `requires` entries exit 1 naming the missing requirement. Unresolvable or missing non-requires entries emit a single stderr warning and are skipped. Added startup TCP connectivity check in `policy::check_tcp_port` (`TcpStream::connect_timeout`). Total startup overhead with `--with flutter` measured at 10.79 ms avg (min 9.65 ms); toolchain resolution adds ~0.75 ms vs base execution (< 100 ms budget). Embedded `[toolchains.flutter]` in `src/profiles.toml` with `requires = ["${bin:flutter}", "${bin:flutter}/../../packages/flutter_tools"]`, Flutter SDK (`${bin:flutter}/../..`), `.pub-cache`, `.gradle/caches`, `.gradle/wrapper`, and `.dartServer` in `rw_cache`; Android SDK (`${ANDROID_HOME:-Android/Sdk}`), `.android/debug.keystore`, and `.config/flutter` in `runtime`; and adb TCP check (`127.0.0.1:5037`). Verified secrets isolation (`~/.gradle/gradle.properties` and `~/.android/adbkey` hidden), host adb server guard refusal (`ADB_REJECT_KILL_SERVER=1` rejects `adb kill-server` inside cave), missing server warnings, and doctor diagnostics. Verified live device workflow: `flutter build apk --debug` succeeded under cave in 14.3s (reusing Gradle caches); `flutter run` on a connected OnePlus 8T (`KB2000`) started the app and hot-reloaded modified `lib/main.dart` across the sandbox in 438ms. Test suite expanded to 37 unit tests and 21 boundary tests (58 tests total, all passing, 0 clippy warnings), with boundary test fixture for fake toolchains and separate verified mutation checks for 1a (Case 5), 1b (Case 4), and the symlink case (`test_resolve_entry_symlink_to_home_is_invalid`).
  - Rationale: `docs/architecture_design.md` › Toolchains; argument: `vdesign/proposals/toolchain-profiles.md` at `b5015eb`. Accepted 2026-11-08.
  - Plan, thin path first:
    1. `[toolchains.*]` table (embedded and user file), `--with NAME` (unknown name fatal), `runtime` and `rw_cache` with literal `$HOME`-relative and host-absolute paths, rendered after the agent profile. A literal test toolchain mounts end to end.
    2. Expansion (`${VAR}`, `${VAR:-default}`, `${bin:NAME}`) as a pure function over a lookup, resolved in `main.rs`; `requires` fatal; unresolved entries warned and skipped; `/` and `$HOME` warnings on resolved paths.
    3. `check_tcp`, and `cave --doctor --with NAME`.
    4. Built-in `flutter` toolchain; live verification on the dogfood host with a host-provided device (needs the user).
    5. Reconcile design documents and README; remove the pending marks.
  - Done when:
    - `cave --with flutter sh -c 'flutter doctor -v'` finds Flutter, the Android SDK and the Android toolchain, with no write errors from read-only paths.
    - Under `cave --with flutter claude`: `flutter build apk --debug` succeeds, and `flutter run` installs on a host-provided device with hot reload working.
    - `--with` an unknown name exits 1; `--with flutter` without `flutter` on `PATH` exits 1 naming the missing entry; with no host adb server, the startup warning shows the hint.
    - Inside `cave --with flutter`, `~/.gradle/gradle.properties` and `~/.android/adbkey` are not visible.
    - `cave --doctor --with flutter` prints each entry, what it resolved to, and the `check_tcp` result.
    - Whether a host adb server started with `ADB_REJECT_KILL_SERVER=1` refuses `adb kill-server` from inside cave is tested, and the docs and the `check_tcp` hint match the result.
    - Startup overhead with `--with flutter` is measured and stays < 100 ms.
    - Unit tests for expansion and the new entry kinds; a boundary test with a fake toolchain on `PATH` (no real Flutter needed); a mutation check on `requires`. Tests and clippy (`-D warnings`) green.
    - `docs/architecture_design.md`, `docs/product_specification.md` and README match what was built.
- [ ] Phase 7: Versioning — `cave --version` names its build
  - Rationale: `docs/architecture_design.md` › Packaging & Distribution › Versioning. Accepted 2026-11-10.
  - Plan, thin path first:
    1. `build.rs` embeds `git describe --long --tags --dirty`; `cave --version` prints it after the `Cargo.toml` version, or the version alone without git metadata. Works before any tag exists (`--always` hash).
    2. Release `0.2.0`: `Cargo.toml` to `0.2.0`; `pkgver()` without the hard-coded fallback; annotated tag `v0.2.0` on that commit, pushed together with it (the user approves the push).
    3. Package build and host upgrade.
    4. Reconcile design documents and README; remove the pending marks.
  - Done when:
    - `Cargo.toml` is the only file that states the release number; `pkgver()` has no hard-coded version.
    - From the package, `cave --version` prints `cave 0.2.0 (v0.2.0-N-gHASH)` naming the same commit as `pacman -Q cave-git` (`0.2.0.rN.gHASH-1`).
    - A local build of a tree with uncommitted changes ends in `-dirty`; after a commit, or an edit under `src/`, the next `cargo build` shows the new state without `cargo clean`.
    - Built without git metadata (a source tree with no `.git`), `cave --version` prints `cave 0.2.0`, and the build does not fail.
    - `pkgver()` on a clone with no reachable tag fails the build.
    - Annotated tag `v0.2.0` points at the commit that sets `version = "0.2.0"`, and is on GitHub.
    - On the host, `pacman -U` upgrades `cave-git` from `0.1.0.r35.gac678da-1` to `0.2.0.r…` without a downgrade warning (needs the user).
    - A test pins the `--version` format; tests and clippy (`-D warnings`) green.
    - `docs/architecture_design.md`, `docs/product_specification.md` and README match what was built, including the release steps (bump, commit, tag, push) and discarding `makepkg`'s `pkgver=` rewrite.

- Candidate: Opt-in Docker access for projects whose agents need `docker compose`; the socket is hidden by default (see `docs/product_specification.md` › Scope).
- Candidate: `hide = [...]` class in the profile table, so a user file can remove an inherited default instead of only downgrading it. Deferred 2026-10-22 until a concrete need; it renders as a tmpfs mount, the mechanism that already hides `$HOME`.
- Candidate: Per-project profile file (`./.cave/profiles.toml`) behind an explicit opt-in flag. Deferred 2026-10-22: the working directory is agent-writable, so the file could widen the boundary it defines.
- Candidate: `--profile NAME` option to choose the agent profile explicitly, replacing selection by command basename, which misses agents launched through wrappers (`cave npx @anthropic-ai/claude-code`, `cave uv run aider` select `npx` / `uv`). Kept separate from `--with` in the toolchain proposal (decided 2026-11-08): `--profile` replaces the agent profile, `--with` adds toolchains to the session.
